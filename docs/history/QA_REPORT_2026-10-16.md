# DQ Command Center V2 — QA, Security & Stabilization Report

**Date:** 2026-10-16 · **Branch:** `master` (uncommitted working tree) · **Scope:** whole application, run locally via Docker Compose

## 1. Summary

The app starts, all four services are healthy, and the main workflows now work end to end in a real browser (Chrome driven by Playwright). This was checked in Swedish and English and at desktop and mobile widths. The flows covered are registration, login, lockout, logout, session refresh, forgot/reset password, profile edits and password change, dataset upload, profiling, scanning, cleaning, versioning and download, admin user/role/department management, and the audit log.

The reported registration crash is fixed at the root. Fixing it surfaced more serious defects. The worst were:

- **dataset files could be read and downloaded by any signed-in user (IDOR);**
- **in the current `development` configuration, anyone could reset any account's password;**
- every self-registered user got a role-less account where every page answered 403.

All three are fixed and covered by regression tests.

Previously generated documents in the repo root (`FINAL_PRIVATE_BETA_VALIDATION_REPORT.md`, `PUBLIC_BETA_READINESS_REPORT.md`, etc.) claim that dataset ownership was "enforced (verified)". **It was not.** The 11 `/dataset-files/*` endpoints had no ownership checks, and the old `tests/test_rbac.py` asserted `True` or only checked a database insert. Treat those documents as superseded by this one.

**Totals:** 29 issues found and fixed. 26 of them were confirmed by an executed test (automated, browser or live API); QA-17, QA-18 and QA-19 were checked only by type-check or build. 16 known limitations or open risks remain (section 5); none of them blocks local use, but **R-1 and R-2 block inviting outside testers** until the configuration is changed.

## 5. Remaining issues and limitations

| ID | Sev | Description | Impact / recommendation |
|---|---|---|---|
| R-1 | **High** (beta blocker) | `.env` has `ENVIRONMENT=development`. That seeds demo users `demo1–3@dqcommandcenter.io` whose password is hard-coded in the repo (`seed_secure.py`). Since QA-04 they also have the `User` role, and `/docs` is public | Before inviting anyone: set `ENVIRONMENT=production` (this also enforces strong secrets) and deactivate the demo accounts in Users |
| R-2 | **High** (beta blocker) | The stack serves the **Vite dev server** behind nginx, and ports 5432/8000 are published on the host | For a beta, use the `production` frontend build target and stop publishing DB/backend ports |
| R-3 | Medium | Aggregate quality metrics (health score, trends, monitoring, results reports) are still computed across **all** datasets | Product decision: org-wide by design, or per user? Only aggregates are exposed — no rows or names — but per-dataset `dataset_id` filters on those endpoints aren't access-checked |
| R-4 | Medium | Email verification is neither enforced nor completable without SMTP | Configure SMTP for the beta, or remove the verify step from the UX |
| R-5 | Low | Changing your password doesn't sign out your other sessions (resetting does) | Consider revoking other refresh tokens on change |
| R-6 | Low | "Account is locked" is shown only for existing accounts (small enumeration signal) | Accept, or use a generic message |
| R-7 | Low | With port 8000 published, a client on the Docker host can send a forged `X-Forwarded-For` straight to the backend | Dev only; goes away with R-2 |

## 6. How to run

```powershell
cd <project folder>
docker compose up -d --build          # never use "down -v": it deletes the database volume
docker compose ps                     # expect postgres/backend/nginx healthy
# App:  http://localhost        API docs (dev only): http://localhost/docs

# Tests
docker exec dq-backend python -m pytest -q -p no:logging
cd frontend; npx tsc -b; npx vitest run; npm run build
```

To finish password-reset/verification **locally without SMTP**, set `DEV_EXPOSE_AUTH_TOKENS=true` in `.env` and recreate the backend. Never do this on a machine other people can reach.
